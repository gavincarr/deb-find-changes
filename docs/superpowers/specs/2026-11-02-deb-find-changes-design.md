# deb-find-changes — design

Date: 2026-11-02
Status: approved by owner 2026-11-02

## 1. Intent

`deb-find-changes` is the Debian/Ubuntu sibling of `rpm-find-changes`
(`~/work/rpm-find-changes`, Perl). It runs on each Debian-family host and
writes a list of **host-local files**: files that are either

- **orphans**: not owned by any installed package, or
- **modified**: owned by a package, but whose contents differ from the
  packaged version.

That list feeds `~/work/extract`, which rsyncs the listed files off every
host onto a backup machine (and, with `post_extract_git`, commits them to
git). The point is to capture host-local changes that were made by hand
rather than through ansible or another config system, so that they are
backed up and visible.

`extract` already expects this tool: its documented Debian-side list path
is `/var/cache/deb-find-changes/etc.txt`, used via
`EXTRACT_FILES_REMOTE="/var/cache/rpm-find-changes/etc.txt /var/cache/deb-find-changes/etc.txt"`.

## 2. Goals, non-goals, anti-goals

**Goals**

- Drop-in counterpart to `rpm-find-changes`: same job, same output
  contract, same nightly-cron deployment shape, near-identical CLI.
- Scan `/etc` by default (via the cron file); accept any directory trees
  on the command line, so other trees (`/usr/local`, `/root`, ...) can be
  added later if they prove useful.
- Correct Debian semantics: dpkg conffiles, ucf-managed config files,
  diversions, removed-but-not-purged packages, packages without md5sums.
- Unattended and quiet in cron: no output on a normal run.

**Non-goals**

- Not a security/integrity tool. dpkg's md5sums are not tamper-proof and
  the tool makes no claims there.
- Not reporting *deleted* package files (nothing to back up).
- Not deciding secrets policy beyond shipping an opt-in exclude block
  (see §6). Encrypting or segregating secrets, if ever wanted, belongs in
  `extract`, not here.
- No handling of `/usr`-merge path aliasing (`/lib` vs `/usr/lib`) in v1;
  irrelevant to `/etc`. Revisit if a `/usr`-side tree is ever scanned.

**Anti-goals** (failure even if it "works")

- **Silently missing a real host-local change.** This is the failure that
  matters. When the tool can't tell, it **includes** the file. Extra files
  cost a little disk and git noise; a missed file defeats the backup.
- Producing a list that makes `extract`'s rsync fail (e.g. a dangling
  symlink, which with `--copy-links` is an rsync error and marks the host
  failed).
- Aborting the whole run because of one bad file (the Perl version `die`s
  on an unreadable file).
- Ever leaving a truncated/half-written list where `extract` can read it.

## 3. Output contract (consumed by extract)

- One **absolute path per line**, sorted (byte order), newline-terminated,
  no prefixes — rsync reads it verbatim with `--files-from`.
- With `-t`/`--type`, each line is `M <path>` or `O <path>` (interactive
  use only; never in the cron file).
- A path containing a newline can't be represented: skip it with a
  warning.
- `-O <file>`: write to a temp file in the same directory, then rename
  over the target, mode `0600`. Without `-O`, write to stdout.
- `extract` runs rsync with `--archive --copy-links --files-from`, so a
  listed symlink is copied as its target's contents.

## 4. Classification rules

Walk each tree argument. Consider only **regular files** and **symlinks
whose target resolves to a regular file** (same as the Perl version's
`File::Find::Rule->file`, which follows symlinks). Skip directories,
dangling symlinks, symlinks to directories, sockets, FIFOs and devices.
Don't descend into symlinked directories.

For each candidate path, after excludes (§5):

| Situation | Result |
|---|---|
| Path is a symlink owned by a package, and the package records no checksum for it (i.e. it shipped as a symlink) | skip (dpkg records no target/checksum for symlinks) |
| Path is a symlink owned by a package that *does* record a checksum for it (a shipped regular file replaced locally by a symlink) | hash the target like any owned file; normally **modified** (`M`) |
| Not owned by any package, not in ucf registry | **orphan** (`O`) |
| Owned, checksum recorded, matches | not listed |
| Owned, checksum recorded, differs | **modified** (`M`) |
| Owned, but no checksum available (package ships no `.md5sums`, conffile hash is `newconffile`, etc.) | **modified** (`M`), warning at `-v` |
| Owned, file unreadable (e.g. not run as root) | **modified** (`M`), warning |
| In ucf registry (generated by maintainer scripts) | verify against ucf hash like an owned file |
| Conffile of a removed-but-not-purged (`rc`) package | verify against its recorded conffile hash |
| Unowned symlink pointing at a regular file (e.g. systemd `*.wants/` enablement links) | **orphan** |

Each orphan is listed once. A file owned by several packages (shared
conffiles, `Multi-Arch: same`) is modified if it fails *any* owner's
checksum it has one for.

### Data sources (read directly; no per-file `dpkg` calls)

All under a configurable dpkg admin dir (default `/var/lib/dpkg`, same
meaning as dpkg's `--admindir`) and ucf dir (default `/var/lib/ucf`):

- **Ownership:** `info/*.list` — one absolute path per line. File names
  may carry an arch qualifier (`bind9-libs:amd64.list`); the package name
  is the part before `:`. These files exist only for installed (and
  half-installed) packages, not for `rc` packages.
- **File checksums:** `info/*.md5sums` — `<md5>  <path-without-leading-slash>`.
  Some packages ship none. A few packages list files under `etc/` here
  that are not conffiles.
- **Conffile checksums:** the `Conffiles:` field of each stanza in
  `status` (deb822). Continuation lines are
  ` <path> <md5-or-"newconffile"> [obsolete|remove-on-upgrade]`. Present
  for `rc` packages too, which is how their leftover conffiles stay owned.
  Status of a package comes from its `Status:` field.
- **Diversions:** `diversions` — repeating 3-line records: original path,
  diverted-to path, diverting package (`:` = local admin diversion). A
  file at the diverted-to path is owned by the package that originally
  shipped the original path, and is checked against that package's
  checksum for the *original* path. A locally diverted file (package `:`)
  at the original path is an orphan. Diversion handling is
  best-effort; getting it slightly wrong must err towards listing.
- **ucf:** `<ucfdir>/hashfile` — `<md5>  <path>`; `<ucfdir>/registry` —
  `<package> <whitespace> <path>`. A path in the registry is owned (by
  that package); its expected checksum comes from `hashfile`. In registry
  but not in hashfile → `M` with warning (per the "when in doubt,
  include" rule).

dpkg uses MD5 for all of the above, so `crypto/md5` is the only digest
needed. If a recorded hash isn't 32 hex chars, treat as "no checksum
available".

Parse everything once at startup into in-memory maps; hash only files
that are under the scanned trees and owned. `/etc` is small; no
concurrency is required, though the builder may add it.

## 5. Excludes

Same three sources as the Perl version:

- `-x, --exclude=<glob>` (repeatable)
- `--exclude-from=<file>` (repeatable): one pattern per line; blank lines
  and `#` comments ignored; a line `@<package>` excludes that package
  (its files are neither verified nor reported — they're simply dropped)
- `--exclude-package=<pkg>` (repeatable; alias `--exclude-pkg`)

Built-in, always-on excludes (the Debian analogue of the Perl version's
`*.rpmnew *.rpmsave`): `*.dpkg-dist *.dpkg-old *.dpkg-new *.dpkg-tmp
*.dpkg-bak *.ucf-dist *.ucf-old *.ucf-new`.

### Pattern semantics

Keep the Perl version's semantics where they worked; fix where they were
broken (`core*` and `.*.sw?` never matched anything, `?` was passed
through as a regex quantifier, `.` handling was ad hoc).

| Pattern form | Meaning | Example |
|---|---|---|
| No `/` | glob matched against the **basename** | `*~`, `core*`, `.*.sw?`, `*.bak` |
| Starts with `/` | glob matched against the **full path**, or any leading path prefix ending at a `/` boundary (so a directory excludes its subtree) | `/etc/alternatives`, `/etc/rc*.d`, `/etc/*/log/main` |
| Contains `/` but doesn't start with it; trailing `/` | directory name anywhere in the path | `.git/`, `.svn/` |
| Other relative patterns with `/` | glob matched against any `/`-aligned suffix of the path | `ssl/private/*` |

Glob metacharacters: `*` (any run of chars, **including** `/`, matching
the Perl behaviour), `?` (one char), `[...]` classes. Everything else is
literal. A pattern that fails to compile is a usage error naming the
pattern and its source file/line.

`/etc/mtab` must match `/etc/mtab` and `/etc/mtab/...` but **not**
`/etc/mtab.foo` (the Perl version's unanchored prefix match got this
wrong).

## 6. Default exclude file: `/etc/deb-find-changes/exclude-etc`

A Debian-tuned port of `rpm-find-changes/etc/exclude-etc`. Starting
point (builder may tune against a real Debian/Ubuntu `/etc`; owner
reviews):

```
# Editor/backup/VCS noise
*~
*-
*.old
*.bak
*.backup
.*.sw?
.git/
.svn/
.bzr/
.hg/
core
core.[0-9]*

# Generated / cache / runtime state
/etc/alternatives
/etc/ld.so.cache
/etc/.pwd.lock
/etc/.updated
/etc/rc*.d
/etc/ssl/certs
/etc/udev/hwdb.bin
/etc/console-setup/cached*
/etc/*/log/main
/etc/*/supervise

# Secrets. These ARE backed up by default (matching rpm-find-changes).
# Uncomment to keep private keys and credentials out of the backup
# (and out of extract's git history). Note this can't catch secrets
# embedded in ordinary config files (e.g. /etc/mysql/debian.cnf).
#/etc/ssh/ssh_host_*_key
#/etc/ssl/private
#/etc/wireguard
#/etc/krb5.keytab
#/etc/shadow
#/etc/gshadow
#/etc/letsencrypt/archive
#/etc/letsencrypt/keys
```

(`*-` excludes `/etc/passwd-`, `/etc/shadow-` etc., the automatic backup
copies.)

The secrets block is deliberately **commented out by default** (owner's
decision): host keys etc. are kept by default for restore fidelity and
parity with the RPM side; turning it on is a one-line-per-pattern edit,
and the file is a dpkg conffile so local edits survive upgrades.

## 7. CLI

Kong-based, mirroring `rpm-find-changes`:

```
deb-find-changes [flags] <path> [<path> ...]
```

| Flag | Meaning |
|---|---|
| `-m, --show-modified` | report only modified files |
| `-o, --show-orphans` | report only orphans (default: both) |
| `-t, --type` (alias `--show-type`) | prefix lines with `M`/`O` |
| `-x, --exclude=GLOB` | exclude pattern (repeatable) |
| `--exclude-from=FILE` | exclude file (repeatable) |
| `--exclude-package=PKG` (alias `--exclude-pkg`) | exclude package (repeatable) |
| `-O, --output=FILE` | write atomically to FILE (mode 0600) instead of stdout |
| `-v, --verbose` | counter; `-v` progress per package/tree, `-vv` per-file decisions incl. checksum mismatches |
| `--[no-]warnings` (alias `-w`) | emit warnings (default on); cron uses `--no-warnings` |
| `--admindir=DIR` | dpkg admin dir (default `/var/lib/dpkg`) |
| `--ucf-dir=DIR` | ucf state dir (default `/var/lib/ucf`) |
| `--version` | print `deb-find-changes <version>`, exit 0 |
| `-h, --help` | help |

The Perl version's hidden `--only` is dropped (it was a debugging aid;
tests use fixtures instead).

Each path argument must be an existing directory, else usage error.
Relative path arguments are made absolute (output paths are always
absolute). A missing or unreadable `--exclude-from` file is a warning,
not an error, and the run continues (fewer excludes → more files listed,
which is the safe direction). *(Builder-check call.)*

If dpkg's `updates/` journal is non-empty (an interrupted dpkg run, so
the database may be stale), log a warning and continue. *(Builder-check
call.)*

**Exit codes:** `0` success (warnings don't change this); `1` runtime
failure (e.g. dpkg admin dir unreadable, output file can't be written);
`2` usage error. On any failure with `-O`, the previous output file is
left untouched.

**Logging:** `slog` to stderr via `tint`; default level Warn, `-v` → Info,
`-vv` → Debug; `--no-warnings` raises the floor to Error. Results go to
stdout/`-O` only, never through the logger. Apply the kong gotchas from
the `go-stack` skill (usage-on-error to stderr, exit-code guard,
explicit `name:` on every field, `type:"counter"` for `-v`, a
grammar-level parse test).

## 8. Build, packaging, release

Follow the owner's standard Go conventions (skills `go-stack` and
`release-flow`):

- Module `github.com/gavincarr/deb-find-changes` (already in `go.mod`);
  binary at `cmd/deb-find-changes`.
- Version in `internal/version/VERSION`, `//go:embed`'d; `--version`.
- `scripts/release.sh <version>` with the six gates; `debian/changelog`
  is the release gate. Start at `0.1.0`.
- Debian packaging modelled on `~/work/src/dany/debian/` (debhelper 13,
  pre-built static Go binary in `bin/`, no-op `dh_auto_*` overrides).
  Package `deb-find-changes`, `Architecture: amd64` only. Target fleet
  (owner): nothing older than Debian 12 / Ubuntu 22.04, all amd64. Debs
  are built on the `repo` machine and published through the internal apt
  repo. Installs:
  - `/usr/bin/deb-find-changes`
  - `/etc/deb-find-changes/exclude-etc` (conffile)
  - `/etc/cron.d/deb-find-changes` (conffile):
    `0 0 * * * root [ -x /usr/bin/deb-find-changes ] && /usr/bin/deb-find-changes --no-warnings --exclude-from=/etc/deb-find-changes/exclude-etc -O /var/cache/deb-find-changes/etc.txt /etc`
    (guard added per Debian Policy §9.5)
  - `/var/cache/deb-find-changes/` (directory)
  - a man page (generated from the help text or a hand-written page;
    builder's choice)
- No hard runtime dependencies (static binary; no `dpkg` exec needed).
  `Recommends: cron | cron-daemon`, so minimal images without cron get
  a hint rather than a silent never-run. No systemd timer in v1.
  *(Builder-check call.)*
- Build the `.deb` with zstd compression (owner's decision), set
  explicitly (`override_dh_builddeb: dh_builddeb -- -Zzstd`) so it
  doesn't depend on `repo`'s distro default. The fleet (Debian 12+ /
  Ubuntu 22.04+) can unpack zstd; if that ever bites, switch to `-Zxz`.
- **Initial scan on install** (owner's decision): `postinst configure`
  runs the same command as the cron line, but only when
  `/var/cache/deb-find-changes/etc.txt` doesn't exist yet, so a freshly
  installed host isn't reported as failed by `extract` until the first
  midnight run. The scan must never fail the install (`|| true`, with a
  short message on failure); upgrades with an existing list don't
  rescan.
- Licence: GPLv3, matching `rpm-find-changes`.

## 9. Testing

- Unit tests per parser (`.list`, `.md5sums`, `status` Conffiles incl.
  `newconffile`/`obsolete`/`remove-on-upgrade` and `rc` packages,
  `diversions`, ucf `hashfile`/`registry`), using small fixture files.
- Classification tests over a synthetic root: a temp dir standing in for
  `/` plus a fixture admin dir and ucf dir. The builder decides how paths
  in fixtures are re-rooted (e.g. an internal root-prefix option, not
  necessarily user-facing).
- Exclude-pattern table tests, explicitly including the Perl-era broken
  cases (`core*`, `.*.sw?`, `/etc/mtab` vs `/etc/mtab.foo`) and paths with
  spaces and `%`.
- CLI tests via the compiled binary asserting stdout and stderr
  separately; grammar test over `kong.New` + `Parse`.
- Atomic-output test: a failed run leaves an existing `-O` file intact.
- Smoke check on this (Ubuntu) machine: run against real `/etc` as a
  normal user and sanity-check the result (unreadable files appear as
  `M` with warnings; nothing crashes).
